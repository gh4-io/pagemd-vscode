## Overview

The preview panel is a VS Code webview that displays paginated HTML generated by the PageMD CLI. It uses Paged.js for pagination and adds custom controls for zoom, panning, and visual debugging.

### Key Components

| Component | Location | Purpose |
|-----------|----------|---------|
| Preview Panel Provider | `src/providers/preview-panel.ts` | Main webview controller |
| Previewer Script | `media/previewer.js` | Paged.js hooks and dimension extraction |
| Paged.js Polyfill | `media/paged.polyfill.js` | CSS Paged Media runtime |
| Webview HTML | Generated dynamically | Wraps CLI HTML with preview features |

### Architecture Layers

```
┌─────────────────────────────────────────────────┐
│ VS Code Extension Host                         │
│  ├─ PreviewPanel (TypeScript)                  │
│  │   ├─ CLI wrapper (generates HTML)           │
│  │   ├─ Webview HTML generator                 │
│  │   └─ Settings provider                      │
└─────────────────────────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────┐
│ Webview Context (sandboxed)                    │
│  ├─ previewer.js (Paged.js hooks)              │
│  ├─ paged.polyfill.js (pagination engine)      │
│  ├─ Toolbar controls (inline script)           │
│  └─ Dimension labels (injected post-render)    │
└─────────────────────────────────────────────────┘
```

## Component Structure

### PreviewPanel Class

**File:** `src/providers/preview-panel.ts`

**Singleton pattern** - Only one preview panel exists at a time.

**Key responsibilities:**

1. Call CLI to generate HTML
2. Extract body content and styles from CLI output
3. Wrap HTML with webview shell
4. Inject Paged.js runtime
5. Add toolbar and preview features
6. Handle refresh events (save/type)

**Lifecycle:**

```javascript
createOrShow()              // Create or reveal existing panel
  → new PreviewPanel()      // Constructor
    → setupDocumentWatching() // Register save/type listeners
      → update(documentUri)   // Set document to preview
        → refresh()           // Generate and display HTML
          → runPageMD()       // CLI: markdown → HTML
          → renderHtml()      // Wrap and inject into webview
            → wrapHtml()      // Add Paged.js + toolbar
```

**Message handling:**

```javascript
// Webview → Extension
panel.webview.onDidReceiveMessage((message) => {
  switch (message.type) {
    case 'rendered':  // Paged.js finished pagination
      // Log page count
    case 'ready':     // Preview loaded
      // Log ready state
  }
})
```

## Rendering Pipeline

### Step-by-Step Flow

**1. User opens preview** (`Ctrl+Shift+P` → "PageMD: Open Paged Preview")

```javascript
PreviewPanel.createOrShow(extensionUri, outputChannel, profileState)
```

**2. Extension calls CLI**

```javascript
await runPageMD({
  args: ['build', filePath, '-o', 'html', '-p', profile],
  cwd: path.dirname(filePath),
  timeout: 30000
})
```

**3. CLI generates HTML**

- Parses Markdown with frontmatter
- Applies profile template and CSS
- Returns complete HTML document

**4. Extension extracts content**

```javascript
// Extract body content
const bodyMatch = html.match(/<body[^>]*>([\s\S]*)<\/body>/i);
const bodyContent = bodyMatch[1];

// Extract inline styles
const styleMatches = html.matchAll(/<style[^>]*>([\s\S]*?)<\/style>/gi);
```

**5. Extension wraps HTML**

```javascript
wrapHtml(content, nonce, themeClass)
  → Generates new HTML document with:
    - CSP meta tag (security)
    - CLI styles (extracted)
    - Preview styles (settings-based CSS)
    - Toolbar HTML + inline script
    - Paged.js script tags
    - Original body content
```

**6. Webview loads HTML**

```javascript
this.panel.webview.html = webviewHtml;
```

**7. Paged.js runs**

```javascript
// In webview context (previewer.js)
window.PagedConfig.before = async () => {
  setup();  // Move styles to head, extract content
};

window.PagedConfig.after = async (flow) => {
  addClassToContentRoots();
  moveTrailingSpaceCharacters();
  injectDimensionLabels();  // If enabled
  notifyRendered();  // Message to extension
};
```

**8. Toolbar initializes**

```javascript
// Inline script in toolbar HTML
window.addEventListener('pagedjs-complete', () => {
  initToolbar();  // Position toolbar at bottom-right
});
```

## CSS Cascade Architecture

### The VS Code CSS Bleeding Problem

VS Code injects default styles into webviews that can override document styling. As of VS Code 1.103+, these defaults are wrapped in `@layer vscode-default`, but preventing style bleeding requires explicit layer management.

**VS Code's Default Webview CSS:**

```css
@layer vscode-default {
  body {
    color: var(--vscode-editor-foreground);
    font-family: var(--vscode-font-family);
    font-weight: var(--vscode-font-weight);
    font-size: var(--vscode-font-size);
    /* ... more VS Code theming ... */
  }
  code {
    font-family: var(--monaco-monospace-font);
    color: var(--vscode-textPreformat-foreground);
    background-color: var(--vscode-textPreformat-background);
  }
  blockquote {
    background: var(--vscode-textBlockQuote-background);
  }
  /* ... etc ... */
}
```

### Layer Order Declaration

**File:** `src/providers/preview-panel.ts:597`

```css
@layer vscode-default, pagemd-preview, base, primary, layout, syntax, profile, frontmatter;
```

**Priority (lowest → highest):**

| Layer | Source | Purpose |
|-------|--------|---------|
| `vscode-default` | VS Code | Webview defaults (must be overridden) |
| `pagemd-preview` | Extension | Preview shell (`media/styles/preview-*.css`) |
| `base` | CLI | Foundation (`project/pagemd/styles/base.css`) |
| `primary` | CLI | Project styles (`project/pagemd/styles/primary.css`) |
| `layout` | CLI | Page structure (`project/pagemd/layouts/*.css`) |
| `syntax` | CLI | Code highlighting |
| `profile` | CLI | Profile visual styles |
| `frontmatter` | Document | Per-document overrides |

### Extension CSS Layer

All extension CSS files are wrapped in `@layer pagemd-preview`:

| File | Purpose |
|------|---------|
| `preview-base.css` | Webview shell (html, body, .pagemd-content) |
| `preview-layout.css` | Page layout (.pagedjs_pages, .pagedjs_page) |
| `preview-toolbar.css` | Zoom toolbar |
| `preview-dimensions.css` | Dimension labels |
| `preview-book.css` | Two-column spread |
| `preview-error.css` | Error display |
| `preview-debug.css` | Debug visualization |

**Example wrapping:**

```css
/* preview-layout.css */
@layer pagemd-preview {

.pagedjs_pages {
  background-color: var(--pagemd-bg-color, #777777);
  /* ... */
}

.pagedjs_page {
  background-color: var(--pagemd-paper-color, #ffffff);
  /* ... */
}

} /* end @layer pagemd-preview */
```

### The Paged.js Problem

**Critical:** Paged.js generates UNLAYERED CSS during pagination. In CSS cascade rules, unlayered CSS always beats layered CSS regardless of layer order.

**Solution:** Document styles use `!important` injection for critical properties:

**File:** `src/providers/preview-panel.ts:550-567`

```typescript
const criticalProps = [
  'font-family',
  'font-size',
  'font-weight',
  'line-height',
  'color',
  'background-color',
  'background',
];
for (const prop of criticalProps) {
  const regex = new RegExp(`(${prop}\\s*:\\s*)([^;!]+)(;)`, 'gi');
  styles = styles.replace(regex, '$1$2 !important$3');
}
```

### base.css Strengthening

To prevent VS Code defaults from showing through, `base.css` explicitly defines all properties that VS Code sets:

| Element | VS Code Sets | base.css Must Define |
|---------|--------------|---------------------|
| `body` | font-family, font-size, font-weight, color, margin, padding | All of these |
| `code` | font-family, color, background-color, padding, border-radius | All of these |
| `a:hover` | color | color |
| `blockquote` | background, border-color | background, border-left |
| `kbd` | All styling | All styling |
| `video` | max-width, max-height | max-width, max-height |
| Focus states | outline, outline-offset | outline, outline-offset |

### What Doesn't Work

Several isolation approaches were attempted but failed:

| Approach | Why It Failed |
|----------|--------------|
| Shadow DOM | Paged.js doesn't render into shadow containers |
| Iframe isolation | Blocked by VS Code CSP |
| JavaScript theme class removal | VS Code re-enforces classes |
| CSS layers alone | Paged.js generates unlayered CSS |

### References

- VS Code issue #261430: https://github.com/microsoft/vscode/issues/261430
- CSS Cascade Layers spec: https://www.w3.org/TR/css-cascade-5/#layering

## CSS Variable System

### Variable Injection

CSS variables are injected by `getPreviewStyles()` method:

```typescript
private getPreviewStyles(): string {
  const config = vscode.workspace.getConfiguration('pagemd');
  const highlightMargins = config.get<boolean>('preview.highlightMargins', true);
  const pageGap = config.get<string>('preview.pageGap', '10mm');
  const zoom = config.get<number>('preview.zoom', 100);

  let css = `:root {
    --pagemd-margin-color: ${marginColor};
    --pagemd-paper-color: ${paperColor};
    --pagemd-bg-color: ${bgColor};
    --pagemd-page-gap: ${pageGap};
    --pagemd-spread-gap: ${spreadGap};
    --pagemd-font-color: #000;
    --pagemd-zoom: ${zoom / 100};
  }`;

  // Conditional CSS based on settings
  if (highlightMargins) {
    css += `...`;
  }

  return css;
}
```

### Variable Usage

**In preview CSS:**

```css
.pagedjs_pages {
  background-color: var(--pagemd-bg-color);
  zoom: var(--pagemd-zoom);
}

.pagedjs_page {
  background-color: var(--pagemd-paper-color);
  margin: var(--pagemd-page-gap) 0;
}

[class*="pagedjs_margin-"] {
  box-shadow: 0 0 0 1px inset var(--pagemd-margin-color);
}
```

**In toolbar script:**

```javascript
// Read CSS variable for gap calculation
const columnGap = safePx(pagesStyle.columnGap);  // --pagemd-page-gap
```

### Variable Lifecycle

1. **Read from settings** - `vscode.workspace.getConfiguration('pagemd')`
2. **Convert to CSS variables** - `:root { --pagemd-zoom: 1.0; }`
3. **Inject into webview** - Inside `<style>` tag in `wrapHtml()`
4. **Apply to elements** - CSS rules use `var(--pagemd-zoom)`
5. **Update on refresh** - Settings changes trigger `refresh()` → regenerates CSS

### Scroll Boundary System

When content is zoomed (200%+), scrolling should show equal spacing on both left and right edges. This is achieved with real DOM spacer elements injected by `zoom-toolbar.js`.

**Why DOM spacers instead of CSS:**

| Approach | Result |
|----------|--------|
| `margin-right` on zoomed element | Browser clips right margin at viewport edge |
| Padding with `border-box` | Padding subtracted from width |
| Padding with `content-box` | Creates unwanted scroll at 100% zoom |
| CSS pseudo-elements | Blocked scrolling to left edge |
| **Real DOM spacers** | ✅ Works - elements participate in scroll calculation |

**Implementation (zoom-toolbar.js):**

```javascript
function adjustScrollBoundary() {
  const content = document.querySelector('.pagemd-content');
  const pages = document.querySelector('.pagedjs_pages');

  // Convert to inline-flex for shrink-wrap behavior
  content.style.display = 'inline-flex';
  content.style.minWidth = '100%';

  // Create spacer elements (if not exist)
  let leftSpacer = content.querySelector('.pagemd-scroll-spacer-left');
  let rightSpacer = content.querySelector('.pagemd-scroll-spacer-right');

  if (!leftSpacer) {
    leftSpacer = document.createElement('div');
    leftSpacer.className = 'pagemd-scroll-spacer-left';
    content.insertBefore(leftSpacer, content.firstChild);
  }

  if (!rightSpacer) {
    rightSpacer = document.createElement('div');
    rightSpacer.className = 'pagemd-scroll-spacer-right';
    content.appendChild(rightSpacer);
  }

  // Style spacers (60px fixed width)
  leftSpacer.style.cssText = 'flex: 0 0 60px;';
  rightSpacer.style.cssText = 'flex: 0 0 60px;';

  // Center pages between spacers
  pages.style.marginLeft = 'auto';
  pages.style.marginRight = 'auto';
}
```

**Why this works:**

1. **`inline-flex` + `min-width: 100%`**: Container shrink-wraps to content when larger than viewport, fills viewport when smaller
2. **Real DOM spacers**: Actual `<div>` elements participate in scroll area calculation (unlike pseudo-elements)
3. **`margin: 0 auto` on pages**: Centers the zoomed content between spacers
4. **Spacers always present**: Transparent when not in debug mode, visible (magenta/cyan) in debug mode

### Scroll Bounds

The **primary bounding box** that defines where scrollbars stop is `.pagedjs_pages`:

```css
.pagedjs_pages {
  /* Size to content (all pages) */
  width: min-content;
  height: min-content;

  /* Center in viewport */
  display: flex;
  flex-direction: column;
  align-items: center;

  /* Apply zoom factor */
  zoom: var(--pagemd-zoom);

  /* Background extends to content edge */
  background-color: var(--pagemd-bg-color);

  /* Padding creates breathing room around pages */
  padding: 100px;
}
```

**Why this matters:**

- `min-content` sizing ensures the container only wraps the pages, not the viewport
- Scrollbars appear when zoomed content exceeds viewport
- The 100px padding provides space for dimension labels

## Toolbar Implementation

### Why Inline Styles for Fixed Positioning?

**Problem:** Paged.js transforms all CSS from `<style>` tags and linked stylesheets during pagination. It removes `position: fixed` entirely because fixed positioning conflicts with paginated document layout.

**Solution:** Use inline `style=""` attributes for fixed positioning since Paged.js only processes CSS in `<style>` tags and `<link>` elements - it does NOT modify element inline styles.

```html
<!-- WRONG: position:fixed gets stripped by Paged.js -->
<style>
.pagemd-zoom-toolbar { position: fixed; bottom: 20px; right: 20px; }
</style>
<div class="pagemd-zoom-toolbar">...</div>

<!-- CORRECT: inline styles bypass Paged.js CSS transformation -->
```

### Zoom Implementation

**CSS zoom vs. transform:**

The toolbar uses CSS `zoom` property instead of `transform: scale()`:

```javascript
function updateZoom() {
  const pages = document.querySelector('.pagedjs_pages');
  // Use CSS zoom - properly affects layout and scrollbars

  // Clear any transform
  pages.style.transform = 'none';
```

**Why zoom over transform:**

- `zoom` affects layout - scrollbars appear when content overflows
- `transform: scale()` is visual only - scrollbars don't update
- Better UX for navigating zoomed content

### Fit-to-Width Calculation

```javascript
function fitToWidth() {
  const parent = pages.parentElement;
  const availableWidth = parent.clientWidth - paddingLeft - paddingRight;
  const pageWidth = page.offsetWidth;

  // Proportional padding: 5% of page width on each side
  const proportionalPadding = pageWidth * 0.10;

  let contentWidth;
  if (bookMode) {
    // Book mode: 2 pages + column gap + padding
    contentWidth = (pageWidth * 2) + columnGap + proportionalPadding;
  } else {
    // Single mode: page + margins + padding
    contentWidth = pageWidth + marginLeft + marginRight + proportionalPadding;
  }

  // Calculate zoom to fit
  zoomLevel = Math.floor((availableWidth / contentWidth) * 100);
  zoomLevel = Math.max(25, Math.min(400, zoomLevel));
  updateZoom();
}
```

## View Mode Architecture

### Three View Modes

| Mode | State | What's Shown |
|------|-------|--------------|
| Paged | `viewMode = 'paged'` | Paginated content via Paged.js |
| Browser | `viewMode = 'browser'` | Raw HTML in iframe (no pagination) |
| Book Spread | `bookMode = true` (overlay on paged) | Two-column CSS Grid layout |

### View Mode Toggle

```javascript
let viewMode = 'paged';  // 'paged' or 'browser'

  }

```

### Browser View Security Model

**Threat Model:** Isolating potentially untrusted HTML content in browser mode.

Browser mode displays raw CLI-generated HTML in an iframe with multiple defense layers to prevent script execution and limit capabilities.

**Defense Layers:**

1. **Iframe Sandbox Attribute:**
   ```html
   <iframe id="pagemd-browser-view"
           sandbox="allow-scripts allow-same-origin"
           class="pagemd-browser-iframe">
   </iframe>
   ```

   | Sandbox Flag | Purpose |
   |--------------|---------|
   | `allow-scripts` | Required for inline styles rendering (no actual scripts in content) |
   | `allow-same-origin` | Allows blob: URL loading (restricted by CSP) |

2. **CSP Meta Tag Injection:**

   Before creating blob URL, CSP meta tag is injected into HTML content:

   ```javascript
   function injectCSP(html) {
     const cspTag = `<meta http-equiv="Content-Security-Policy"
       content="default-src 'self' blob: data:;
                script-src 'none';
                style-src 'unsafe-inline' blob: data:;
                img-src 'self' blob: data: https:;
                font-src 'self' blob: data:;">`;

     // Inject after <head> tag
     return html.replace(/<head[^>]*>/i, match => match + cspTag);
   }
   ```

**CSP Policy Details:**

| Directive | Value | What It Does |
|-----------|-------|--------------|
| `default-src` | `'self' blob: data:` | Default policy for resource loading |
| `script-src` | `'none'` | **Blocks ALL external scripts** |
| `style-src` | `'unsafe-inline' blob: data:` | Allows inline styles and CSS from blob/data URIs |
| `img-src` | `'self' blob: data: https:` | Allows images from same origin, blob, data URIs, and HTTPS |
| `font-src` | `'self' blob: data:` | Allows fonts from same origin, blob, and data URIs |

**What Runs:** Inline styles and fonts only (required for rendering styled HTML).

**What's Blocked:**
- External scripts (`<script src="...">`)
- Inline scripts (`<script>...</script>`)
- `javascript:` URLs
- Event handlers (`onclick`, `onerror`, etc.)
- Iframes
- Forms
- Popups
- Object/embed elements

**Security Guarantees:**

Browser mode ensures:
- No arbitrary code execution from CLI-generated HTML
- No external resource fetching (except images/fonts)
- No form submission or user data exfiltration
- No popup or navigation hijacking

### Blob URL Persistence (C3)

**Performance Optimization:** Reuse blob URLs when content unchanged.

**Implementation:**

```javascript
let blobUrl = null;
let lastContentHash = null;

function simpleHash(str) {
  let hash = 0;
  for (let i = 0; i < str.length; i++) {
    const char = str.charCodeAt(i);
    hash = ((hash << 5) - hash) + char;
    hash = hash & hash; // Convert to 32bit integer
  }
  return hash;
}

function toggleViewMode() {
  if (viewMode === 'paged') {
    // Switching to browser mode
    const rawHtml = window.pagemdRawHtml;
    const currentHash = simpleHash(rawHtml);

    // Reuse blob URL if content unchanged
    if (currentHash === lastContentHash && blobUrl) {
      iframe.src = blobUrl;
      iframe.classList.add('active');
    } else {
      // Content changed - revoke old blob and create new one
      if (blobUrl) {
        URL.revokeObjectURL(blobUrl);
      }

      const blob = new Blob([rawHtml], { type: 'text/html' });
      blobUrl = URL.createObjectURL(blob);
      lastContentHash = currentHash;

      iframe.src = blobUrl;
      iframe.classList.add('active');
    }

    viewMode = 'browser';
  } else {
    // Switching to paged mode
    viewMode = 'paged';
    iframe.classList.remove('active');

    // Keep blob URL for potential reuse
    // Only revoke on content refresh or disposal
  }
}
```

**Revocation Strategy:**

| Event | Action | Reason |
|-------|--------|--------|
| Content refresh | Revoke + create new | HTML changed |
| Panel disposal | Revoke | Prevent memory leak |
| View mode switch | Keep blob | May switch back |
| `beforeunload` | Revoke | Page unloading |

**Memory Leak Prevention:**

```javascript
// Global cleanup handler
window.addEventListener('beforeunload', function() {
  if (blobUrl) {
    URL.revokeObjectURL(blobUrl);
    blobUrl = null;
  }
});

// Panel disposal cleanup

  if (blobUrl) {
    URL.revokeObjectURL(blobUrl);
    blobUrl = null;
  }
});
```

## Dimension Label System

### Extraction Before Paged.js

**Problem:** Paged.js removes @page rules from CSS after processing.

**Solution:** Extract layout info in `before` hook, cache it, use in `after` hook.

```javascript

  cachedLayoutInfo = extractLayoutInfo();
};

window.PagedConfig.after = async (flow) => {
  // Use cached info AFTER Paged.js finishes
  if (window.pagemdSettings?.showDimensions && cachedLayoutInfo) {
    injectDimensionLabels(cachedLayoutInfo, unit);
  }
};
```

### Layout Info Extraction

```javascript
function extractLayoutInfo() {
  // Find all @page rules in stylesheets
  const styles = document.querySelectorAll('style');
  const cssText = Array.from(styles).map(s => s.textContent).join('\n');
  const pageRules = [...cssText.matchAll(/@page\s*{([^}]+)}/g)];

  // Score each rule to find the best match
  // (Prefer rules with non-zero margins and named sizes)
  let bestScore = 0;
  let pageBody = '';

  for (const match of pageRules) {
    const body = match[1];
    let score = 0;

    // Non-zero margin = likely the actual layout CSS
    if (body.includes('margin:') && !body.match(/margin:\s*0/)) {
      score += 10;
    }

    // Named size (Letter, A4, etc.)
    if (body.match(/size:\s*(letter|a4|legal)/i)) {
      score += 5;
    }

    if (score > bestScore) {
      bestScore = score;
      pageBody = body;
    }
  }

  // Parse size and margins
  const sizeMatch = pageBody.match(/size:\s*([^;]+)/);
  const marginMatch = pageBody.match(/margin:\s*([^;]+)/);

  return {
    size: parseSizeValue(sizeMatch?.[1] || 'Custom'),
    margins: parseMarginValue(marginMatch?.[1] || '0'),
    padding: parseMarginValue(paddingMatch?.[1] || '0')
  };
}
```

```javascript
function injectDimensionLabels(layoutInfo, unit) {
  const pages = document.querySelectorAll('.pagedjs_page');

  pages.forEach((page, index) => {
    // Create wrapper for positioning context
    const wrapper = document.createElement('div');
    wrapper.className = 'pagemd-page-wrapper';

    const width = convertUnit(layoutInfo.size.width, unit);
    const height = convertUnit(layoutInfo.size.height, unit);
```

### Unit Conversion

```javascript
function convertUnit(value, toUnit) {
  const match = value.match(/([\d.]+)\s*(in|mm|cm|pt|px)?/i);
  const num = parseFloat(match[1]);
  const fromUnit = (match[2] || 'px').toLowerCase();

  // Convert to inches first
  let inches;
  switch (fromUnit) {
    case 'in': inches = num; break;
    case 'mm': inches = num / 25.4; break;
    case 'cm': inches = num / 2.54; break;
    case 'pt': inches = num / 72; break;
    case 'px': inches = num / 96; break;
  }

  // Convert to target unit
  if (toUnit === 'mm') {
    return (inches * 25.4).toFixed(1) + 'mm';
  } else {
    return inches.toFixed(2) + 'in';
  }
}
```

## Hand Tool Architecture

### State Management

```javascript
let handToolActive = false;  // Tool enabled
let isDragging = false;      // Currently dragging
```

### Event Handlers

```javascript
function handleMouseDown(e) {
  if (!handToolActive) return;
  if (e.button !== 0) return;  // Only left click
  if (e.target.closest('.pagemd-zoom-toolbar')) return;  // Skip toolbar

  isDragging = true;
  document.body.classList.add('dragging');

  startX = e.pageX - window.scrollX;
  startY = e.pageY - window.scrollY;
  scrollLeft = window.scrollX;
  scrollTop = window.scrollY;
}

function handleMouseMove(e) {
  if (!isDragging) return;

  const x = e.pageX - window.scrollX;
  const y = e.pageY - window.scrollY;
  const walkX = startX - x;
  const walkY = startY - y;

  window.scrollTo(scrollLeft + walkX, scrollTop + walkY);
}

function handleMouseUp(e) {
  isDragging = false;
  document.body.classList.remove('dragging');
}
```

## Security: Content Security Policy

The webview uses a strict CSP with nonces:

```html
<meta http-equiv="Content-Security-Policy"
  content="default-src 'none';
           style-src ${webview.cspSource} 'unsafe-inline';
           script-src 'nonce-${nonce}';
           img-src ${webview.cspSource} data:;">
```

**Why nonces:**

- Prevents arbitrary script execution
- Only scripts with matching nonce can run
- Nonce changes on every refresh

**Generated by:**

```typescript
function getNonce(): string {
  let text = '';
  const possible = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789';
  for (let i = 0; i < 32; i++) {
    text += possible.charAt(Math.floor(Math.random() * possible.length));
  }
  return text;
}
```
